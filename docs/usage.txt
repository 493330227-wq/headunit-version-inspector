车机版本检测 1.1.0

安装与使用
1. 将「headunit-inspector-1.1.0.apk」复制到 U 盘，在车机文件管理器中点击安装。请在停车时操作。
2. 按车机提示允许该文件管理器安装未知来源应用。无需 Root 或 ADB。
3. 打开「车机版本检测」，自动扫描。结果页先显示「标称版本」和「真实版本（检测推定）」。
4. 点击「查看适配的 DiPlay」进入独立推荐页，点击「前往 GitHub 下载页」跳转。
   GitHub 页面可能是英文；在 Assets（文件）区域选择推荐的 .apk 文件。
   也可以复制下载链接到手机或电脑打开。
5. 如果显示「暂无法可靠推荐」，点击「查看检测依据」。可以长按复制文本，也可以导出/分享文本或 JSON 报告。
6. 下载页由外部浏览器打开；检测本身无需联网。

兼容与权限
检测软件最低 Android 4.0 / API 14；无原生库，适合 ARM、ARM64、x86 等架构。
不申请网络、存储、定位、蓝牙等权限；不修改车机系统设置。
报告保存在本应用缓存，只有用户主动分享时才交给选择的应用；卸载后清除。
这里的 Android 4.0 是检测软件的门槛，不代表 DiPlay 支持 Android 4.0。

推荐规则
API 28 及以上：官方 DiPlay 0.2.12（本地目录截至 2026-10-05，不声称最新版本）。
API 26–27：KrunkZhou Android 8 兼容版 v0.2.6，文件 DiPlay-Android8-complete-debug.apk。
API 19–25：Legacy Android v0.2.7，实验性推荐，实际连接尚需验证。
API 18 及以下：目录中没有已核验的适配包。
接口证据冲突或 CPU 架构未匹配：暂停推荐，展示原因。
目录详情、来源和已核验包的 SHA-256 见 仓库根目录的 catalog.json。


结果边界
“关于设备”的安卓标签和系统报告的 API 都可能被固件修改。
本工具交叉检查公开接口，发现明显矛盾并估计软件兼容门槛，不能保证识别所有伪装。
接口裁剪或回移也可能影响结果；不能把一个接口的存在当成绝对真实版本证明。
满足安装门槛，不代表热点、认证、音频、触控或 CarPlay 连接一定可用。

验证状态
已完成 Java 编译、APK 打包、ZIP 完整性、对齐、v1/v2/v3 签名及 74 项推荐规则检查。
尚未在安卓模拟器或实体车机启动验证，车机安装、界面及系统接口调用需实机确认。
如果检测 APK 也解析失败，保留错误文本；下一步用 ADB 获取安装错误代码，而不是反复更换 U 盘。

演示页面
双击「docs/demo.html」，可在浏览器中切换 7 个模拟场景，体验结果页、推荐页和下载跳转。
演示数据来自 APK 的同一套规则，不代表你的车机真实检测结果。

升级
1.1.0 使用与 1.0.0 相同的包名和签名，可尝试直接覆盖安装，无需先卸载。
若系统阻止安装，请保留具体错误信息。
